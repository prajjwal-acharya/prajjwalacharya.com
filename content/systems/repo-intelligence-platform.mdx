## Why it exists

Understanding an unfamiliar repository still means reading code by hand: tracing imports, guessing at service boundaries, cross-referencing CI configs and Terraform to figure out what actually talks to what. RIG aims to generate that understanding automatically, turning a repository into a queryable graph instead of a pile of files.

## What it aims to do

Ingest a repository's source code, git history, dependency graph, CI/CD, Docker, Kubernetes, OpenAPI specs, database schema, Terraform, and configuration, then produce a service graph, API graph, module graph, dependency graph, ownership graph, and call graph from it. Delivered as a CLI and SDK for generating the graph, a visualization layer for exploring it, and an export API for feeding it into other tools.

## Success metric

Given any repository, generate an accurate engineering graph automatically.

## Current state

The `rig` Python package now has a working end-to-end pipeline:

- **Repository scanning** (`rig.scanner`) — repo discovery, file walking, `.gitignore`/hidden-file handling, metadata collection, snapshot/stats models.
- **Plugin system** (`rig.plugins`) — manifests, discovery, registry, lifecycle/context/capability primitives, a manager with error isolation.
- **Language layer** (`rig.languages`) — a language catalog/registry, detection by file patterns, and language statistics.
- **Parser framework** (`rig.parsers`) — parser interfaces, registry, manager, pipeline, and Tree-sitter integration. Concrete Go support is implemented (parser factory + grammar wiring); broader language support is still planned.
- **Compiler-style analysis pipeline** — IR generation (`rig.ir`), symbol table construction (`rig.symbols`), reference resolution (`rig.references`), type modeling/indexing (`rig.types`), graph generation (`rig.graph`), and semantic analyses (`rig.analysis`) for call graphs, type relationships, and dependencies.
- **CLI** — `scan`, `detect`, `parse`, `ir`, `symbols`, `references`, `types`, `graph`, `analyze`, and `stats` commands, all with dedicated test coverage alongside the scanner/plugins/languages/parsers layers.
